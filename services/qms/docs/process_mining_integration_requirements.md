# Требования к интеграции Process Mining для голосовых команд KMS

Process Mining отвечает только за преобразование аудио в текст. Он не должен менять партии, заказы, статусы, складские остатки или любые бизнес-данные KMS.

## Назначение

KMS отправляет короткую голосовую запись сотрудника хлебозавода в Process Mining. Process Mining распознаёт русскую речь и возвращает результат callback-запросом в KMS.

Целевой сценарий:

1. Сотрудник записывает команду в KMS.
2. KMS сохраняет аудиофайл и отправляет его в Process Mining.
3. Process Mining создаёт задачу распознавания.
4. Process Mining сразу возвращает `task_id` и `status=processing`.
5. После распознавания Process Mining отправляет callback в KMS.
6. KMS показывает текст и найденную команду сотруднику.
7. Только KMS после подтверждения сотрудника выполняет бизнес-действие.

## API Process Mining

### POST `/api/transcriptions/`

Формат запроса: `multipart/form-data`.

Поля:

- `audio_file` - аудиофайл.
- `external_id` - ID `VoiceMessage` в KMS.
- `client_request_id` - уникальный ID клиентского запроса.
- `callback_url` - endpoint KMS для результата.
- `language` - язык, для первой версии `ru`.
- `context` - JSON-строка с контекстом хлебозавода.

Пример `context`:

```json
{
  "stages": ["Очередь", "Замес", "Формовка", "Расстойка", "Печь", "Склад", "Готово"],
  "batch_numbers": ["B-2026-0001-1", "B-154"]
}
```

Авторизация: `Authorization: Bearer <PROCESS_MINING_API_TOKEN>`.

Первичный ответ:

```json
{
  "task_id": "tr-8821",
  "external_id": 821,
  "status": "processing"
}
```

## Callback в KMS

Process Mining должен отправлять результат в `callback_url`, который получает от KMS.

### Успех

```json
{
  "task_id": "tr-8821",
  "external_id": 821,
  "status": "completed",
  "transcript": "Партия B-154 закончила замес, передать на формовку",
  "confidence": 0.96,
  "language": "ru",
  "duration_ms": 1700
}
```

### Ошибка

```json
{
  "task_id": "tr-8821",
  "external_id": 821,
  "status": "failed",
  "error_code": "TRANSCRIPTION_FAILED",
  "error": "Не удалось распознать голос"
}
```

## Подпись callback

Callback должен быть подписан HMAC SHA-256.

Алгоритм:

1. Взять raw body HTTP-запроса в байтах.
2. Посчитать `HMAC-SHA256(raw_body, PROCESS_MINING_CALLBACK_SECRET)`.
3. Передать подпись в заголовке:

```http
X-Process-Mining-Signature: sha256=<hex_digest>
```

Для тестового стенда KMS также поддерживает заголовок:

```http
X-Process-Mining-Secret: <PROCESS_MINING_CALLBACK_SECRET>
```

## Требования к аудио

Process Mining должен сообщить KMS:

- список поддерживаемых форматов;
- максимальный размер файла;
- максимальную длительность записи;
- MIME types;
- требования к частоте дискретизации, если есть.

Минимально ожидаемые форматы:

- `audio/webm`
- `audio/ogg`
- `audio/mpeg`
- `audio/wav`
- `audio/mp4`

## Идемпотентность

Process Mining должен не создавать вторую задачу при повторном запросе с тем же `client_request_id`.

Если запрос повторился, нужно вернуть существующую задачу:

```json
{
  "task_id": "tr-8821",
  "external_id": 821,
  "status": "processing"
}
```

Callback тоже может быть повторён. KMS обрабатывает повторный callback без создания дублей, но Process Mining должен стараться не слать бесконечные повторы.

## Retry и timeout

Process Mining должен:

- быстро принять файл и вернуть задачу;
- распознавать асинхронно;
- использовать timeout для callback;
- повторять callback при временной недоступности KMS;
- логировать ошибки;
- не хранить аудио бесконечно.

Рекомендуемый целевой UX для коротких команд: 2-5 секунд. Нельзя обещать гарантированные 3 секунды, потому что задержка зависит от сети, сервера и размера аудио.

## Распознавание хлебозавода

Нужно хорошо распознавать:

- номера партий: `B-154`, `B-155`, `B-2026-0001-1`;
- этапы: `Очередь`, `Замес`, `Формовка`, `Расстойка`, `Печь`, `Склад`, `Готово`;
- команды: `закончила замес`, `передать на формовку`, `отправить в печь`, `поступила на склад`, `партия готова`, `поставить на паузу`, `возобновить`, `обнаружено подгорание`.

Process Mining возвращает только текст и уверенность. Структурирование команды и выполнение делает KMS.

## Что нужно предоставить KMS-команде

- точный URL API;
- способ авторизации;
- тестовый API URL;
- тестовый токен;
- список аудиоформатов;
- максимальный размер файла;
- максимальную длительность;
- формат ответа;
- формат callback;
- алгоритм HMAC;
- timeout;
- retry policy;
- список возможных `error_code`;
- Swagger/OpenAPI документацию;
- примеры `curl`.
