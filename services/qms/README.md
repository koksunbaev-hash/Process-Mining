# Bakery QMS

Система адаптирована под хлебозавод: она управляет заказами на хлебобулочную продукцию, рецептурами, производственными партиями, этапами производства, проблемами, голосовыми сообщениями и складом готовой продукции.

Основной процесс:

```text
Новый заказ -> Очередь -> Замес -> Формовка -> Расстойка -> Печь -> Склад -> Заказ готов
```

## Возможности

- Производственная Kanban-доска: Очередь, Замес, Формовка, Расстойка, Печь, Склад, Готово.
- Заказы с клиентом, сроком, приоритетом и несколькими позициями.
- Автоматическое создание производственных партий после подтверждения заказа.
- Продукты, ингредиенты и рецептуры с backend-расчётом потребности ингредиентов.
- История движения партии между этапами: откуда, куда, кто, когда, комментарий и длительность.
- Проблемы производства на базе существующих несоответствий QMS с дополнительными связями с заказом, партией, продуктом и этапом.
- Голосовые сообщения с записью в браузере через MediaRecorder API и защищённой выдачей файлов только авторизованным пользователям. Интерфейс сначала пробует писать `m4a`, если браузер поддерживает `audio/mp4`; иначе использует `webm` или `ogg`.
- Склад готовой продукции, который пополняется при переходе партии на этап «Склад».
- Dashboard и отчёты по заказам, партиям, этапам, проблемам, складу и голосовым сообщениям.
- REST API с serializers, ViewSets, permissions, filters, search и pagination.

## Роли

- Администратор: полный доступ.
- Диспетчер производства: заказы, партии, назначение ответственных, движение между этапами.
- Технолог: продукты, рецептуры, ингредиенты, расчёты.
- Операторы замеса, формовки, расстойки и печи: работа со своим этапом.
- Складской сотрудник: приём готовой продукции и склад.
- Руководитель: просмотр системы и отчётов.
- Аудитор: просмотр истории и документов.

Проверки прав выполняются на backend в `apps/bakery/permissions.py` и сервисах движения партий.

## Голосовые сообщения

Файлы сохраняются в:

```text
media/voice_messages/YYYY/MM/
```

В базе хранится путь и метаданные, не base64. Разрешены `m4a`, `webm`, `ogg`, `mp3`, `wav`. На практике браузер выбирает формат сам: Safari чаще поддерживает `m4a`, Chrome/Edge часто сохраняют `webm`. Настройка лимита:

```env
MAX_VOICE_MESSAGE_SIZE_MB=20
```

Аудио выдаётся через защищённый view `/bakery/voice/<id>/audio/`. Прямую публичную ссылку через `MEDIA_URL` для рабочей логики использовать не нужно.

## Установка и запуск

```powershell
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
python manage.py migrate
python manage.py seed_bakery
python manage.py runserver
```

## Тесты

```powershell
python manage.py check
python manage.py test
```

Тесты покрывают создание продуктов, ингредиентов, рецептур, расчёт ингредиентов, создание заказов и партий, переходы этапов, историю, запрет перехода без прав, блокировку проблемной партии, склад, голосовые сообщения, Kanban-фильтрацию, отчёты и API-защиту.

## Миграции и старые данные

Старые QMS-приложения и модели не удалены. Раздел несоответствий расширен связями с хлебозаводом, но прежние записи остаются совместимыми. Старые контрольные разделы можно переносить постепенно: сначала сопоставить `QualityObject` с продуктами/партиями, затем закрыть или архивировать старые маршруты контроля.
