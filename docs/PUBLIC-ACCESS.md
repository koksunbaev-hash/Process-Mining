# Публикация наружу и доступ из любой точки

Задача: показать проект потребителям из интернета, самому заходить по SSH из
VS Code откуда угодно, бесплатно и без домена — не открывая при этом виртуалку
всему миру.

Решение — **Tailscale**. Один демон закрывает обе задачи:

- **Funnel** выдаёт публичный адрес `https://<машина>.<tailnet>.ts.net` с
  настоящим сертификатом. Порты на роутере не пробрасываются, белый IP не
  нужен, работает из-за NAT.
- **Тайлнет** даёт приватный путь к SSH: порт 22 в интернет не смотрит, а
  VS Code Remote-SSH видит машину как обычный хост.

Бесплатного тарифа хватает: 3 пользователя, 100 устройств, Funnel включён.

---

## 0. Что нужно сделать до публикации

Не пропускайте этот раздел. Пока он не выполнен, публиковать нечего — снаружи
будет стоять система с паролями из публичного репозитория.

### 0.1 Сменить все демо-пароли

В `seed_bakery.py` десять пользователей с паролями вида `Admin123!`, и этот
файл лежит в открытом репозитории. Сгенерировать новые и показать их один раз:

```bash
docker compose exec -T qms python manage.py shell -c "
import secrets, string
from django.contrib.auth import get_user_model
alphabet = string.ascii_letters + string.digits
for u in get_user_model().objects.order_by('username'):
    pwd = ''.join(secrets.choice(alphabet) for _ in range(16))
    u.set_password(pwd); u.save()
    print(u.username, pwd, sep='\t')
"
```

Сохраните вывод в менеджер паролей. В git его не класть, в чат не вставлять.
Учётки, которые на показе не нужны, лучше выключить совсем:

```bash
docker compose exec -T qms python manage.py shell -c "
from django.contrib.auth import get_user_model
get_user_model().objects.exclude(username__in=['admin','dispatcher','mixing']).update(is_active=False)
"
```

Важно: `seed_bakery` без `--reset-passwords` пароли существующих пользователей
не трогает, так что повторный сев ничего не вернёт обратно. С флагом —
вернёт, поэтому после публикации его не запускать.

### 0.2 Проверить `.env`

```bash
grep -E '^(DEBUG|SECRET_KEY|PM_API_KEYS|DB_PASSWORD|BIND_ADDR)' .env
```

- `DEBUG=False` — иначе первая же ошибка покажет трейсбек с содержимым настроек.
- `SECRET_KEY`, `PM_API_KEYS`, `PM_CALLBACK_SECRET`, `DB_PASSWORD` — не значения
  из `.env.example`. Если что-то осталось шаблонным: `openssl rand -hex 32`.
- `BIND_ADDR` — либо отсутствует (тогда действует новый умолчательный
  `127.0.0.1`), либо явно `127.0.0.1`.

### 0.3 Забрать изменения и пересобрать

```bash
cd ~/Process-Mining && git pull && docker compose up -d --build
```

**Что при этом изменится, к этому надо быть готовым:**

| Было | Стало |
|---|---|
| `http://192.168.0.137:8000` работал | больше не отвечает — порты 8000/8001 теперь на loopback |
| `http://192.168.0.137:8001` работал | там же |
| вход по http где угодно | куки только по https (`SESSION_COOKIE_SECURE`) |
| рейт-лимита не было | 12 попыток входа в минуту с адреса, 30 r/s на остальное |

В локальной сети всё живёт по прежним адресам с TLS: `https://192.168.0.137`
и `https://192.168.0.137:8443`.

## 1. Tailscale на виртуалке

```bash
curl -fsSL https://tailscale.com/install.sh | sh
sudo tailscale up --ssh
```

Команда напечатает ссылку — открыть её в браузере и войти (Google/GitHub/почта,
аккаунт создаётся там же). После этого машина появится в вашем тайнете.

`--ssh` включает Tailscale SSH: вход по вашей личности из тайнета, без раздачи
ключей. Обычный `sshd` при этом продолжает работать в локальной сети, ничего
настраивать не надо.

Узнать имя машины в тайнете:

```bash
tailscale status
```

Оно вида `dt.tail1234.ts.net` — дальше по тексту это `<host>`.

## 2. Публичный адрес

Funnel требует, чтобы у тайнета были включены HTTPS-сертификаты и у машины —
атрибут `funnel`. Первый запуск сам напечатает ссылку на нужный переключатель в
админке, если чего-то не хватает.

```bash
sh services/tailscale/publish.sh
```

Скрипт делает две вещи:

```
funnel :443  -> https+insecure://127.0.0.1:443   -> nginx -> qms
funnel :8443 -> https+insecure://127.0.0.1:8443  -> nginx -> process-mining
```

Через nginx, а не напрямую в приложения: там рейт-лимиты и заголовок
`X-Forwarded-Proto`, без которого Django отвергает каждую отправленную форму.
`https+insecure` — потому что на том конце самоподписанный сертификат от
`make-cert.sh`, а хоп идёт по петле, где некому подделываться.

**Если у вас старая версия tailscale** и `--https=` ругается:

```bash
tailscale serve --bg https:443 / https+insecure://127.0.0.1:443
tailscale funnel 443 on
```

### Сказать Django новое имя

Django отвечает `400` на незнакомый `Host`, поэтому в `.env`:

```bash
ALLOWED_HOSTS=127.0.0.1,localhost,qms,192.168.0.137,<host>
CSRF_TRUSTED_ORIGINS=https://<host>,https://192.168.0.137
```

```bash
docker compose up -d qms
```

Проверить снаружи — с телефона по мобильному интернету, не из той же сети:

```
https://<host>/         QMS
https://<host>:8443/    консоль аналитики
```

### Когда адрес устоялся — включить HSTS

```bash
# .env
SECURE_HSTS_SECONDS=31536000
```

```bash
docker compose up -d qms
```

Раньше времени не включать: браузер запомнит требование https на год, и отменой
настройки это не отыгрывается.

### Снять публикацию

```bash
sh services/tailscale/publish.sh off
```

Мгновенно и без следов: адрес перестаёт отвечать, стек продолжает работать в
локальной сети и в тайнете.

## 3. SSH из VS Code

На вашем компьютере (Windows) — поставить Tailscale с
<https://tailscale.com/download> и войти в тот же аккаунт. Проверить:

```bash
tailscale status
ssh dt_qms@<host>
```

В VS Code: расширение **Remote - SSH**, затем `F1` → *Remote-SSH: Open SSH
Configuration File* → добавить

```
Host qms-vm
    HostName dt.tail1234.ts.net
    User dt_qms
```

Дальше `F1` → *Remote-SSH: Connect to Host* → `qms-vm`. Работает из любой сети:
дома, в кафе, с мобильного модема — трафик идёт по тайнету, порт 22 в интернете
не открыт вообще.

Первое подключение ставит на виртуалку VS Code Server (~100 МБ в `~/.vscode-server`).

Если `ssh` не пускает: Tailscale SSH проверяет личность, а не ключ, — убедитесь,
что оба устройства в одном тайнете (`tailscale status` показывает обе строки) и
что на виртуалке демон поднят с `--ssh`.

## 4. Проверка после публикации

```bash
# порты приложений больше не торчат в сеть
ss -tlnp | grep -E '8000|8001'        # ожидаем только 127.0.0.1

# TLS снаружи настоящий, без предупреждений
curl -sI https://<host>/ | head -3

# рейт-лимит на входе работает
for i in $(seq 1 20); do curl -s -o /dev/null -w "%{http_code} " https://<host>/login/; done
# в конце должны пойти 429

# аналитика без ключа не отдаёт данные
curl -s -o /dev/null -w "%{http_code}\n" https://<host>:8443/api/v1/logs   # 401
```

Контейнеры целы: `docker compose ps` — пять штук, все `Up`.

### Одна вещь, которую стоит посмотреть глазами

Рейт-лимит считает по адресу клиента, а через Funnel запрос приходит от
локального демона. nginx восстанавливает исходный адрес из `X-Forwarded-For` —
но только если Tailscale его прислал. Проверить:

```bash
docker compose logs --tail=20 proxy
```

Если в строках доступа стоит адрес вида `172.x.x.x` для запросов, сделанных
снаружи, заголовка нет, и тогда все зрители из интернета считаются одним
клиентом: 12 попыток входа в минуту на всех. Для показа это лечится
повышением лимита в `services/nginx/nginx.conf`:

```
limit_req_zone $binary_remote_addr zone=login:10m rate=60r/m;
```

Занижать обратно после показа.

## 5. Что остаётся небезопасным

Публикация не чинит то, что записано в [HANDOFF](HANDOFF.md) — говорить об этом
честнее, чем ждать вопроса.

- **`tenant` фильтрует, но не изолирует.** Один API-ключ технически может
  прочитать данные другого тенанта. Пока ключ один и он ваш — это не эксплуатируется,
  но раздавать ключи разным потребителям нельзя.
- **Рейт-лимит теперь есть только в nginx.** Внутри приложений его нет, поэтому
  интеграция, которая ходит в аналитику напрямую по контейнерному имени, не
  ограничена ничем.
- **Консоль аналитики открыта всем** — сама страница грузится без ключа. Данные
  без `X-API-Key` она не покажет, но факт существования сервиса виден.
- **Ключ вводится в браузере** и лежит в `localStorage`. На чужом компьютере
  после показа — выйти и почистить.
- **Событие может застрять в `PROCESSING`**, `Idempotency-Key` меняется на
  каждой попытке, ключ кеша `/mine` не включает содержимое файла. Всё это не
  про доступ снаружи, но всплывёт при нагрузке.
- **Бэкапа нет.** `postgres_data` живёт только на этой виртуалке.

## Чего не делать

- Не возвращать `BIND_ADDR=0.0.0.0` «чтобы удобнее» — это открывает http без
  шифрования, включая страницу входа.
- Не пробрасывать порты на роутере. Funnel даёт то же самое, но виртуалка не
  светится сканерам.
- Не запускать `seed_bakery --reset-passwords` на опубликованном стенде: он
  вернёт пароли из репозитория.
- Не показывать `/admin/` посторонним. Демонстрация живёт на канбан-доске.
