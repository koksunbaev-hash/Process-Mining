Система, которая ведёт производство —
и система, которая показывает, как оно шло

QMS ведёт заказы, партии и качество. Process Mining принимает от него поток событий и строит карту реального процесса: где партии стоят, какие маршруты встречаются, сколько времени съедает каждый переход. Общая база у них не предусмотрена — только HTTP-контракт.

Карта процесса
Где партии стоят, какие маршруты встречаются, сколько времени съедает каждый переход.
Аналогия. QMS — журнал: кто что сделал и когда. Process Mining — карта, собранная из этого журнала. Журнал никто не читает построчно, карту видно сразу.
Почему два сервиса. Тяжёлый расчёт карты не должен мешать принимать заказы. Аналитику можно перезапустить в любой момент — она не хранит ничего незаменимого.
Связь односторонняя. QMS шлёт события, аналитика их принимает. Общей базы нет — только HTTP. Обратно идёт лишь одна вещь: результат распознавания голосовой команды.
Голос — тот же путь. Оператор говорит вместо того, чтобы тянуть карточку мышью. Событие получается такое же, просто руки остаются в тесте.
01 — Обзор

Кто чем занят

Разделение простое: одно приложение владеет бизнес-данными, второе — ничем, что нельзя пересчитать. Поэтому тяжёлый расчёт карты процесса не может уронить приём заказов.

QMS — источник событий

Django 5 + PostgreSQL. Заказы, производственные партии, канбан-доска по этапам, контроль качества, несоответствия, склад, оборудование, отчёты, голосовые команды. Каждое значимое действие пишется в локальную таблицу-outbox.

Django 5PostgreSQL gunicorn 3×4:8000

apps/: accounts · audit · bakery · dashboard · equipment · inspections · nonconformities · notifications · process_mining · quality · reports

Process Mining — потребитель

FastAPI + pm4py. Принимает event log, хранит его, строит карты процессов, считает KPI, варианты маршрутов и узкие места, рисует SVG/PNG. Плюс веб-консоль на трёх языках и модуль распознавания речи.

FastAPIpm4py pandasgraphvizSQLite:8001

core/: ingestion · model · mapping · filtering · mining · metrics · rendering · cache

Почему не одно приложение

QMS должен продолжать принимать заказы, даже когда дискавери на большом логе выедает ядро. Аналитика не хранит ничего незаменимого и может перезапускаться когда угодно. Объединять их — значит обменять эту изоляцию ни на что: они и так общаются по чистому HTTP-контракту. Объединён жизненный цикл: один клон, один .env, один docker compose up.

Граф отдельно от картинки

SVG нельзя кликнуть, отфильтровать или анимировать. JSON-граф с частотами и длительностями отдаётся в любой фронтенд. Картинка остаётся для отчётов.

pm4py заперт в одном файле

Его публичный API дрейфует между минорными версиями. Все вызовы — в core/mining.py, единственное исключение — pm4py.read_xes в core/ingestion.py: читать XES больше некому.

Тяжёлое — в пул потоков

pm4py и graphviz блокируют. На event loop они положили бы весь сервис, поэтому идут через JobManager: /discover/async → job_id → GET /jobs/{id}. Одновременно — два задания.

05 — Голосовой контур

Руки в муке — форму никто не заполнит

Оператор удерживает кнопку (или пробел) и говорит. QMS не ждёт распознавания: получает task_id мгновенно, результат приходит callback-ом. Медленная модель не роняет интерфейс, а команда не выполняется сама — партию двигает подтверждение человека.

Почему HTTPS обязателен

Браузер даёт микрофон только в защищённом контексте. http://<ip> не подходит, localhost подходит. TLS здесь — не про секретность, а единственный способ включить голос на чужом компьютере.

Речь не произносит пунктуацию

Whisper пишет B107, в базе B-107. Точное сравнение не сходится — сравниваются только буквы и цифры.

Что честно сказать про границы

Задержка 2–4 секунды на четырёх ядрах без GPU. Точность в цеху рядом с печью не измерена. Разбирается речь, а не смысл: номера партий и этапы — по словарю и регулярным выражениям.

06 — Интерфейс

API аналитики

Префикс /api/v1, авторизация X-API-Key или Authorization: Bearer. Живая версия — /docs (Swagger) и /redoc. Два пути намеренно живут вне /api/v1: контракт приёма событий и приём аудио согласованы раньше, чем появился сервис.

07 — Решения

То, что не надо переделывать

Каждое из них стоило времени и объясняет, почему код выглядит именно так.

идемпотентность Две независимые защиты

По event_id — событие с уже известным идентификатором считается дубликатом; гарантия закреплена частичным уникальным индексом в БД, а не аккуратностью вызывающего кода. По Idempotency-Key — повторный пакет возвращает тот самый ответ, ничего не импортируя. Без этого любой ретрай задваивал бы метрики.

раскладка Отдельный лог на каждый case_type

Заказ, производственная партия и продажа живут разными жизненными циклами. Одна карта на всех описывала бы процесс, которого не существует. Лог создаётся сам при первом событии, его id детерминированно выводится из пары (source, case_type) — источнику не нужно ничего хранить.

хранилище За интерфейсом из трёх методов

LogRepository: сегодня SQLite, завтра Postgres или parquet в S3 — API-слой не заметит. Реализация для Postgres пока не написана, и это единственная причина ограничения в одну реплику.

голос Плагин, а не ядро

Whisper требует гигабайты RAM и не нужен 90% потребителей. Живёт за флагом и импортируется лениво — сервис стартует меньше чем за секунду. Распознавание умеет только распознавать: разбор команды и её выполнение остаются в QMS, с подтверждением человеком.

Грабли, на которые уже наступили

  • Аргументы вызова считаются до самого вызова. Кнопка «Дальше →» в последней колонке доски давала 500: следующий этап вычислялся перед переходом, а его не существует.
  • messages.get_messages(request).used — это не «ошибок не было». Флаг значит «сообщения отрендерены»; при JSON-ответе их никто не рендерит, и drag&drop всегда рапортовал успех. Смотреть надо на result.ok, а не на response.ok: отклонённый перенос — это честный HTTP 200.
  • Демо утекало в рабочий лог. Фильтр сделан подзапросом по id, а не через batch__is_demo: по nullable-ключу Django строит LEFT OUTER JOIN, а PostgreSQL не даёт SELECT … FOR UPDATE по внешней стороне такого соединения. На SQLite это не видно — FOR UPDATE игнорируется.
  • Два воркера uvicorn ломали асинхронные задания. Реестр заданий и кеш живут в памяти процесса: discover/async отдавал job_id из одного воркера, а GET /jobs/{id} попадал в другой и отвечал 404.
  • pm4py падает с KeyError, если активность встречается только в кейсах из одного события: узла нет, а в стартовые она попадает. Передавать только то, что реально нарисовано.
  • PowerShell 5.1 портит UTF-8. Кириллица в Get-Content/Set-Content превращается в мохибейк — для таких файлов Python или bash.

Что система не делает

Архитектурные ограничения

  • Хранилище аналитики — SQLite, значит одна реплика этого сервиса.
  • tenant — фильтр, не изоляция. Он сужает выборку, но не мешает одному ключу прочитать данные другого.
  • Дискавери упирается в CPU. Большие логи — только через /discover/async.
  • Образ ~1 ГБ: pm4py тянет scipy и matplotlib.

Открыто после сверки кода 3 августа 2026

  • Событие может застрять в PROCESSING навсегда. Статус ставится в транзакции, снимается кодом после HTTP-вызова. Падение процесса во время запроса — и событие не подберёт ни выборка PENDING, ни ретрай FAILED.
  • Idempotency-Key меняется на каждой попытке. Приём умеет вернуть исходный ответ по ключу, но QMS шлёт новый export_id на каждый вызов. Реально от задвоения спасает только дедуп по event_id.
  • Ключ кеша POST /mine не включает содержимое файла. У statistics/variants/bottlenecks нет флага use_cache=False: два клиента с разными файлами и одинаковыми фильтрами получают один ключ.
  • Загрузка лога блокирует единственный процесс. Разбор CSV/XES идёт синхронно внутри async def — пока read_xes жуёт большой файл, сервис не отвечает ни на что.

Закрыто веткой demo-hardening

  • Демо больше не попадает в событийный лог: событие несёт is_demo, экспорт пропускает демо-партии и демо-заказы, сброс демо убирает свои неотправленные события.
  • Дашборд считает цех, а не демо.
  • Аналитика запущена в один процесс — асинхронные задания снова находятся.
  • Заказ готов, когда готовы все его партии, а не первая из них.
  • Доска не падает на последней колонке и честно показывает отказ переноса.
  • На чистом клоне поднимается прокси — шаг с сертификатом теперь в README.

Что выяснено про данные 1С

База живая: 106 549 документов реализации. Но связей между документами нет — ДокументОснование и Сделка пусты во всех проверенных проведённых документах, проследить путь одной сделки нечем. Восстанавливать связи по суммам и датам нельзя: получится уверенная картинка процесса, которого не существует. Поэтому кейс = контрагент + месяц — это отвечает на вопрос «как идёт работа с клиентом и где застревает». Время суток недостоверно (документы проводят пачками), работаем с точностью до дня.

Последняя выгрузка: 12 464 документа → 1295 событий, 903 кейса. Надёжная находка — счёт-фактуру выписывают через 11.5 дней после отгрузки (медиана). А вот цифру «43.7% только отгрузка» называть долей нарушений нельзя: это частично артефакт нарезки по календарным месяцам.

09 — Запуск

Поднять у себя

Шаг с сертификатом не опциональный: сертификаты генерируются на хост и не коммитятся, поэтому на свежем клоне services/nginx/certs/ просто нет, и прокси уходит в бесконечный рестарт.

Весь стек

# один .env на оба сервиса: SECRET_KEY и PM_API_KEYS
cp .env.example .env
openssl rand -hex 32

# адрес, который люди будут набирать — он уедет в subjectAltName
sh services/nginx/make-cert.sh 192.168.0.137

docker compose up -d --build

QMS — :8000, консоль аналитики — :8001, Swagger — :8001/docs.

По отдельности и полезное

cd services/process-mining
pip install -r requirements-dev.txt
pytest -q
uvicorn app.main:app --reload --port 8001
# нужен бинарь graphviz на PATH

# демо-данные для показа
docker compose exec qms python manage.py seed_bakery
docker compose exec qms python manage.py create_kanban_demo --count 13 --user admin

# разовая выгрузка из 1С
docker compose exec process-mining python -m app.connectors.onec --days 60

Проверить приём событий руками

CSV=events.csv
CHK=$(sha256sum "$CSV" | cut -d' ' -f1)

curl -X POST http://<host>:8000/api/event-logs/import/ \
  -H "X-API-Key: <token>" \
  -H "Idempotency-Key: $(uuidgen)" \
  -F "file=@$CSV" \
  -F "export_id=$(uuidgen)" \
  -F "source=kms_bakery" \
  -F "schema_version=1.0" \
  -F "checksum=$CHK"
