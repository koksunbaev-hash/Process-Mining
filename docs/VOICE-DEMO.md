# Голосовое управление: как показать

Прототип. Собран из готовых частей: интерфейс записи, разбор команды и
перевод партии уже были в QMS — не хватало только распознавания речи, и его
добавили отдельным контейнером.

## Что происходит по нажатию кнопки

```
оператор                QMS                 process-mining          STT
   │                     │                        │                  │
   ├─ держит кнопку ────>│                        │                  │
   │  говорит            ├─ audio ───────────────>│                  │
   │                     │<── task_id (сразу) ────┤                  │
   │                     │                        ├─ PCM ───────────>│
   │                     │                        │<── текст ────────┤
   │                     │<── callback + подпись ─┤                  │
   │<─ «B-154 → Формовка,│                        │                  │
   │    подтвердить?»    │                        │                  │
   ├─ подтверждает ─────>│                        │                  │
   │                     ├─ партия переходит      │                  │
   │                     ├─ событие ─────────────>│ карта процесса   │
```

Ключевое: QMS **не ждёт** распознавания. Он получает `task_id` мгновенно и
показывает результат, когда тот придёт. Поэтому медленная модель не роняет
интерфейс.

Второе ключевое: команда **не выполняется сама**. Оператор видит, что система
поняла, и подтверждает. Ошибка распознавания не двигает партию.

## Сценарий показа (5 минут)

**1. Открыть канбан-доску.** `http://<ip>:8000` — видны партии по этапам.

**2. Нажать кнопку записи и сказать:**

> «Партия B-154 закончила замес, передать на формовку»

**3. Показать, что система поняла.** Появится распознанный текст и разобранная
команда: партия `B-154`, действие — перевод на этап «Формовка».

**4. Подтвердить.** Партия переезжает на доске.

**5. Открыть карту процесса.** `http://<ip>:8001`, выбрать в списке
`kms_bakery · production_batch` — переход, который только что сделали голосом,
уже в карте, и видно, сколько времени партия провела на каждом этапе.

Пятый шаг — самый важный для разговора с руководством: голос это не игрушка,
а способ получить данные о процессе оттуда, где у людей руки в муке и никто не
будет заполнять формы.

## Что говорить про ограничения

Честнее сказать самому, чем услышать вопрос:

- **Точность в цеху не проверена.** Whisper `small` по-русски работает хорошо
  на чистой записи. Как он поведёт себя рядом с работающей печью — покажут
  только записи с производства.
- **Задержка 2–4 секунды.** На четырёх ядрах без видеокарты. С GPU — меньше
  секунды, но это отдельные деньги.
- **Распознаётся речь, а не смысл.** Номера партий и этапы разбираются
  регулярными выражениями по готовому словарю. Свободные формулировки вроде
  «ну это, которое с утра ставили» система не поймёт.

## Если распознаёт плохо

Модель меняется одной строкой в `.env`, перезапуск занимает минуту:

```bash
STT_MODEL=base     # быстрее, менее точно
STT_MODEL=small    # по умолчанию
STT_MODEL=medium   # точнее, но на CPU слишком медленно
```

```bash
docker compose up -d stt
```

Прогоните на реальных записях из цеха и выберите по факту.

## Проверка перед показом

Убедитесь, что все четыре контейнера живы:

```bash
docker compose ps
```

Speech-сервис отвечает:

```bash
curl -s localhost:8001/api/transcriptions/capabilities
```

Первый запуск скачивает модель (~0.5 ГБ), поэтому **первое распознавание будет
долгим**. Прогрейте его до показа: запишите любую фразу заранее.
