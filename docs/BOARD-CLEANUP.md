# Утренняя уборка колонки «Готово»

«Готово» — последний этап на доске: дальше партия не едет. Без уборки
колонка копила карточки бесконечно, и к восьми утра смена подходила к
доске, на которой вчерашнее вперемешку с сегодняшним.

Теперь в 7:55 колонка пустеет, и в 8:00 смена начинает с чистого листа.

## Ничего не удаляется

Это главное. Убирается только показ на доске — строки остаются на месте:

| что | зачем оно нужно |
|---|---|
| история этапов `BatchStageHistory` | из неё строится карта процесса |
| она же | из неё считаются столбцы смен в листе «Заказ на производство» |
| она же | из неё уходит поток в общий InfluxDB |
| склад готовой продукции | держит партии через `PROTECT` |

Удалить это ради чистой доски значило бы поменять отчётность на косметику.
Убранную партию по-прежнему видно в списке партий, в поиске и в карточке
заказа — пропадает она только с доски.

## Два механизма, и они подстраховывают друг друга

**Отметка.** Команда `clear_done_board` проставляет партии
`board_cleared_at`. Она же печатает, что именно убрала, — есть кого
спросить.

**Граница производственного дня.** Доска сама не показывает то, что
доехало до последних наступивших 8:00.

Одной команды было бы мало: стенд ночью выключали, и доска встретила бы
смену грязной. Одной границы — тоже: она молчаливая, по ней не спросишь,
что и когда ушло. Вместе — чисто в любом случае.

### Почему граница именно «последние наступившие 8:00»

Не «сегодня в 8:00». Ночная смена печёт с восьми вечера до восьми утра, и
в три часа ночи её выпуск обязан оставаться на доске. Взяли бы сегодняшние
восемь — он пропадал бы прямо из-под рук у смены, которая его и сделала.

В восемь утра граница перешагивает вперёд, и всё сделанное до неё с доски
уходит — включая ночную смену. Так и задумано: доска это рабочий стол, а
не отчёт. Сделанное посчитано в листе заказа и лежит на складе.

## Запуск руками

```bash
cd ~/Process-Mining && docker compose exec -T qms python manage.py clear_done_board
```

Посмотреть, не трогая:

```bash
cd ~/Process-Mining && docker compose exec -T qms python manage.py clear_done_board --dry-run
```

Команда идемпотентна: второй запуск подряд не находит ничего. Пропущенный
запуск не беда — следующий уберёт накопившееся разом.

## Расписание

Стоит в crontab пользователя `dt_qms` на стенде:

```
55 2 * * * cd /home/dt_qms/Process-Mining && /usr/bin/docker compose exec -T qms python manage.py clear_done_board >> /home/dt_qms/clear_done_board.log 2>&1
```

**Время в UTC, и это не опечатка.** Часы стенда идут по UTC, а завод живёт
по `Asia/Qyzylorda`. Смещение там +5 круглый год, перевода часов нет,
поэтому 02:55 UTC — это всегда 07:55 в цеху. Здешний cron
(Ubuntu 3.0pl1-200) не понимает `CRON_TZ`, иначе стояло бы прямо `55 7` с
указанием пояса.

Если стенд переведут на местное время — строку надо поменять на `55 7`,
иначе уборка уедет на пять часов.

Посмотреть расписание и журнал:

```bash
crontab -l && tail -20 ~/clear_done_board.log
```
