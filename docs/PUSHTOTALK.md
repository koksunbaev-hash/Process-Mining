# Приложение и сайт: один голос на двоих

Голосом можно управлять из двух мест — из браузера на канбан-доске и из
Android-приложения. Раньше это были два независимых контура с двумя моделями
Whisper. Теперь модель одна.

---

## Как это устроено

```
браузер ──── webm/opus ────┐
                           │
телефон ──── m4a ──────────┤
                           ▼
                    process-mining
                  /api/transcriptions/       (браузер: task_id + callback)
                  /api/transcriptions/sync   (телефон: текст в ответе)
                           │
                           ▼
                      stt (faster-whisper medium)
                           │
                           ▼
                     распознанный текст
                           │
                           ▼
                     QMS: parse_voice_command
              намерение · партия · этап · количество
                           │
                           ▼
                  VoiceCommand ждёт подтверждения
                           │
                           ▼
                    move_batch → событие → карта процесса
```

Ключевое: **сходятся не только модели, но и разбор**. Текст из браузера и текст
из телефона попадают в одну и ту же `create_voice_command`, поэтому фраза
«партия B-154 закончила замес» означает ровно одно и то же, откуда бы она ни
пришла. Команда в обоих случаях ждёт человека — приложение не двигает партию
само.

Разница только в транспорте:

| | Браузер | Телефон |
|---|---|---|
| Запись идёт в | QMS → аналитику | backend PushToTalk → аналитику |
| Ответ | callback с подписью HMAC | текст на том же соединении |
| Почему так | страница не должна замирать | callback принимать некуда |
| Команда в QMS | из callback-а | `POST /api/pushtotalk/commands/` |

Backend приложения не хранит токен QMS на телефоне: приложение говорит только
со своим backend-ом, а тот уже предъявляет `PUSHTOTALK_API_TOKEN`. Отсюда лишний
хоп — он же единственная причина, по которой токен не лежит в APK.

## Что изменилось при объединении

**Своя модель у PushToTalk убрана.** `faster-whisper` больше нет в
`requirements.txt`, а `transcription_service.py` стал HTTP-клиентом к аналитике.
Минус 1.4 ГБ памяти и минус вторая точка настройки.

**Потеряна подсказка модели.** Локальный faster-whisper получал
`initial_prompt` со списком форматов кодов партий (`DEMO-B-0012`, `MOD-3321`), а
сервер OVOS подсказку по HTTP не принимает. Номера партий будут приходить менее
опрятно — это переживаемо: QMS сравнивает их по буквам и цифрам (`_squash` в
`voice_process_mining.py`), поэтому `B107` и `B-107` для него одно и то же.
Если окажется, что качество просело заметно, вариант — заменить OVOS-контейнер
на собственный сервис поверх `faster-whisper`, где подсказка снова появится.

**Исправлена кодировка.** `app/api/speech.py` и `app/schemas/speech.py` были
записаны UTF-8, а прочитаны cp1251 — весь русский текст в них превратился в
`Р­РЅРґРїРѕРёРЅС‚С‹`. Задет был и `initial_prompt`: модели скармливалась
подсказка из мусора. Это те же грабли, что записаны в HANDOFF про PowerShell
5.1 — файлы с кириллицей редактировать Python-ом или bash, не PowerShell.

## Запуск

Приложение — часть общего стека:

```bash
docker compose up -d --build pushtotalk
```

| Адрес | Что |
|---|---|
| `http://127.0.0.1:8002` | backend приложения (loopback, как и остальные) |
| `https://<host>:10000` | он же через TLS-прокси — этот адрес и вбивается в приложение |

Порт 10000 выбран не случайно: Tailscale Funnel публикует только 443, 8443 и
10000, а телефону нужен публичный HTTPS ровно так же, как браузеру нужен
защищённый контекст для микрофона.

Опубликовать наружу — `sh services/tailscale/publish.sh`: он поднимает все три
порта, включая 10000 для приложения.

### Проверка без телефона

```bash
# backend жив
curl -s http://127.0.0.1:8002/api/health

# распознавание из файла, весь путь целиком
curl -s -X POST http://127.0.0.1:8002/api/speech/transcribe \
     -F "file=@sample.m4a"

# то же самое, но напрямую в аналитику
curl -s -X POST http://127.0.0.1:8001/api/transcriptions/sync \
     -H "X-API-Key: $PM_API_KEYS" \
     -F "audio_file=@sample.m4a"
```

Первый ответ после старта долгий: контейнер `stt` тянет модель.

## Android-клиент

**Приложение из этого репозитория не соберётся.** В `.gitignore` было правило
`data/`, написанное для рантайм-данных, и оно молча выбрасывало из каждого
коммита пакет `app/src/main/java/com/example/push_to_talk/data/` — весь сетевой
слой: `ApiService`, `AuthInterceptor`, репозитории. `NetworkModule.kt` их
импортирует, а в git их нет.

Правило исправлено (теперь `/services/process-mining/data/`), но сами файлы
есть только на машине, где их писали. Их нужно закоммитить:

```bash
git add services/pushtotalk/app/src/main/java/com/example/push_to_talk/data
git commit -m "Add the network layer .gitignore was swallowing"
```

Проверить, что больше ничего не потерялось:

```bash
git status --short services/pushtotalk
```

### Адрес backend-а

Это параметр сборки, а не константа:

```bash
./gradlew assembleDebug -PapiBaseUrl=https://<host>.<tailnet>.ts.net:10000/
```

Слэш в конце обязателен — Retrofit требует его от `baseUrl`. Для эмулятора на
той же машине — `http://10.0.2.2:8002/`.

## Render

На Render едут три сервиса: QMS, аналитика и backend приложения. Распознавание
не едет: Whisper medium — это 1.4 ГБ, free-инстанс даёт 512 МБ. Поэтому и сайт,
и приложение на демо-стенде ходят за распознаванием **на виртуалку** по её
публичному адресу Funnel.

Blueprint — [render.yaml](../render.yaml) в корне. Значения с `sync: false`
вводятся в панели Render один раз: адреса виртуалки, токены и имена хостов.

Что помнить про демо-стенд:

- **Пароли на нём публичные.** `seed_bakery` заводит пользователей с паролями,
  напечатанными в этом репозитории. Стенд — витрина с выдуманными данными;
  настоящие заказы туда не заводить. Приватный контур — на виртуалке, там
  пароли ротируются ([PUBLIC-ACCESS.md](PUBLIC-ACCESS.md)).
- **Диска нет.** SQLite аналитики и история сообщений приложения пропадают при
  каждом перезапуске. Команда от этого не теряется: она уезжает в QMS сразу,
  а он на Postgres.
- **Инстанс засыпает.** Первый запрос после паузы поднимает контейнер, и первое
  распознавание к тому же ждёт виртуалку. Перед показом прогрейте оба.
- **Выключили виртуалку — пропал голос.** Доска, заказы и карта процессов
  продолжат работать, распознавание — нет.
