# ИИ-анализ в Process Mining

В консоли аналитики две вещи умеют говорить словами: **сводка** на вкладке
«Аналитик» и **помощник**, которому там же можно задать вопрос по журналу.
Обе работают через языковую модель, поднятую отдельно, — сервис к ней только
ходит по HTTP.

Ниже: как это устроено, как включить, как проверить и что делать, когда
помощник молчит.

## Главное правило: числа считает сервис

Модель не видит журнала. Ни целиком, ни кусками.

```
журнал событий
   │
   ▼
pandas / pm4py           узкие места, аномалии, маршруты, длительности
   │  готовые числа, уже оформленные («40 мин», а не 2400)
   ▼
языковая модель          складывает из них русский текст
   │
   ▼
экран
```

Отсюда два следствия, ради которых всё и сделано именно так:

* **Соврать про партию модели не на чем.** В тексте те же цифры, что в
  таблицах рядом: она их пересказывает, а не считает.
* **Журнал не утекает.** Наружу уходит выжимка на десяток строк, а не
  события. Даже если модель стоит у соседей, она видит агрегаты.

Помощник устроен так же, только числа берёт не разом, а по запросу: у него
восемь функций к журналу — общие показатели, узкие места, застрявшие дела,
этап, исполнители, путь дела, маршруты, самые долгие дела. Все только
читают. Ни одна ничего не меняет и не ходит наружу.

## Что видит человек

**Вкладка «Аналитик» → «Сводка».** Экран открывается сразу с текстом,
собранным из шаблонов, а через несколько секунд его подменяет пересказ
модели. Подпись у заголовка говорит, чьими словами написано: «обновляется
вместе с журналом» — шаблон, «написано моделью по этим числам» — модель.

**Вкладка «Аналитик» → «Спросить о процессе».** Поле для вопроса и четыре
подсказки для начала. Под каждым ответом мелким шрифтом — куда помощник
ходил за числами («смотрел: узкие места»). Это не украшение: по этой строке
видно, что число взято из расчёта, а не сочинено.

Переписка живёт во вкладке браузера. Сервер её не хранит: закрыли вкладку —
разговора нет.

## Включение

Выключено по умолчанию. Модель в стек не входит — нужен уже поднятый
OpenAI-совместимый сервер (vLLM, Ollama, llama.cpp).

В `~/Process-Mining/.env`:

```
PM_LLM_ENABLED=True
PM_LLM_BASE_URL=http://192.168.0.145:8000/v1
PM_LLM_MODEL=morosystems/ThinkingCap-Qwen3.6-27B-NVFP4
PM_LLM_API_KEY=
PM_LLM_TIMEOUT_SECONDS=30
```

`PM_LLM_API_KEY` оставляют пустым, если у модели нет авторизации: у vLLM,
запущенного без `--api-key`, её нет.

Перезапустить сервис:

```bash
cd ~/Process-Mining && docker compose up -d process-mining
```

### Что за модель внутри DT_Lab

| адрес | модель | как |
|---|---|---|
| `http://192.168.0.145:8000/v1` | `morosystems/ThinkingCap-Qwen3.6-27B-NVFP4` | GX10-7, vLLM, отвечает |
| `http://192.168.0.132:8002/v1` | Qwen 3.8 27B | GX10-17, порт закрыт снаружи |

Со стенда до 192.168.0.145 — 9 мс. Сводка пишется 5–12 секунд, ответ
помощника — 2–4 секунды.

Подойдёт любая другая модель с поддержкой вызова функций: помощник без неё
работать не будет — ему нечем спросить данные. Сводка обойдётся и без.

## Проверка

**Отвечает ли модель вообще:**

```bash
curl -s http://192.168.0.145:8000/v1/models | jq '.data[].id'
```

**Пишет ли сводку модель, а не шаблон** — поле `narrator`:

```bash
curl -s "http://localhost:8001/api/v1/logs/<log_id>/analyst?narrate=1" \
  -H "X-API-Key: <ключ>" | jq '.narrator, .digest[0]'
```

`"llm"` — написала модель, `"templates"` — не дождались, показан шаблон.

**Отвечает ли помощник:**

```bash
curl -s -X POST "http://localhost:8001/api/v1/logs/<log_id>/assistant" \
  -H "X-API-Key: <ключ>" -H "Content-Type: application/json" \
  --data-binary @question.json | jq '.available, .steps, .answer'
```

где `question.json` — файл в UTF-8:

```json
{"question": "где мы теряем больше всего времени?"}
```

Тело запроса лучше слать файлом: кириллица в командной строке Windows
приезжает искажённой.

## Если помощник молчит

| симптом | причина | что делать |
|---|---|---|
| «Помощник не настроен» | нет `PM_LLM_ENABLED=True`, адреса или имени модели | заполнить все три, перезапустить сервис |
| «Модель сейчас недоступна» | не дошли до модели: сеть, адрес, порт | `curl` по `/v1/models` с самого сервера |
| Сводка всегда «обновляется вместе с журналом» | модель не ответила за отведённое время | поднять `PM_LLM_TIMEOUT_SECONDS`, посмотреть логи |
| Ответы приходят, а `steps` пустой | модель не умеет вызывать функции | взять модель с поддержкой tool calling |
| В логе «LLM: пустой ответ» | модель ушла в размышление, весь вывод — reasoning | это лечится в коде (`enable_thinking: false`); если модель игнорирует флаг, взять другую |

Логи:

```bash
docker compose logs --tail=50 process-mining | grep -i llm
```

Ни один из этих случаев не ломает консоль: таблицы, карта и показатели
считаются на месте и от модели не зависят. Худшее, что бывает, — сводка из
шаблонов и помощник, который честно сказал, что молчит.

## Что где лежит в коде

| файл | назначение |
|---|---|
| `services/process-mining/app/core/llm.py` | транспорт: один POST, таймаут, отказ без исключения |
| `services/process-mining/app/core/analyst.py` | числа, шаблонная сводка, `brief` и `narrate` |
| `services/process-mining/app/core/assistant.py` | функции к журналу и разговор с моделью |
| `services/process-mining/app/api/v1/mining.py` | маршруты `/analyst` и `/assistant` |
| `services/process-mining/app/static/studio/studio.js` | сводка и чат в консоли |
| `services/process-mining/tests/test_assistant.py` | тесты (в сеть не ходят) |

## Стоимость

Ноль. Модель уже стоит на своём железе внутри сети, токены никому не
оплачиваются, наружу ничего не уходит. Это и было условием: интеграция
должна быть бесплатной и работать в контуре завода.
