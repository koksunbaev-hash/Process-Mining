# Перед показом

Порядок действий на стенде `192.168.0.137` и проверки, которые ловят
неприятности до того, как их увидит зал. Голосовая часть расписана отдельно —
[VOICE-DEMO.md](VOICE-DEMO.md).

---

## 1. Развернуть

```bash
cd ~/Process-Mining
git fetch origin
git checkout demo-hardening && git pull
docker compose up -d --build qms process-mining
```

Пересобирать нужно оба: в QMS поменялся Python и шаблоны, у аналитики —
`Dockerfile`. Миграций эта ветка не добавляет, но `docker-entrypoint.sh` всё
равно прогонит `migrate` и `collectstatic` сам.

Если прокси ещё ни разу не поднимался на этой машине:

```bash
sh services/nginx/make-cert.sh 192.168.0.137
docker compose up -d proxy
```

Без сертификата `nginx` уходит в бесконечный перезапуск, а без HTTPS браузер не
даст микрофон ни на одном компьютере, кроме локального.

---

## 2. Проверить, что всё живо

```bash
docker compose ps
```

Пять контейнеров в состоянии `Up`: `db`, `qms`, `process-mining`, `stt`,
`proxy`. Любой в `Restarting` — смотреть `docker compose logs --tail 50 <имя>`.

```bash
curl -sk https://192.168.0.137:8443/health/live
curl -sk https://192.168.0.137:8443/api/transcriptions/capabilities -H "X-API-Key: $PM_API_KEYS"
```

Первый отвечает `{"status":"ok",…}`, второй — описанием модели распознавания.

---

## 3. Прогреть

**Распознавание речи.** Первый запуск скачивает модель (~0.5 ГБ) и первое
распознавание идёт долго. Скажите что-нибудь в микрофон заранее — иначе
руководитель будет смотреть на крутящийся индикатор.

**Карту процесса.** Постройте её один раз до показа: результат ляжет в кеш и
на показе нарисуется мгновенно.

---

## 4. Развести демо и цех

Демонстрационные партии больше не попадают ни в событийный лог аналитики, ни в
счётчики дашборда — это правки текущей ветки. Но события, ушедшие в аналитику
**раньше**, там и остались: `case_id` вида `DEMO-B-0001` уже смешаны с
цеховыми в логе `kms_bakery · production_batch`.

Проверить, есть ли они:

```bash
curl -sk https://192.168.0.137:8443/api/v1/logs -H "X-API-Key: $PM_API_KEYS"
```

Дальше — открыть в консоли аналитики лог `production_batch` и посмотреть
вкладку вариантов: демо-кейсы видны по номерам `DEMO-B-…`.

Решать по обстановке. Если на карте видны `DEMO-B-*` и это будет заметно —
удалить лог и дать ему набраться заново из свежих событий:

```bash
curl -sk -X DELETE https://192.168.0.137:8443/api/v1/logs/<log_id> \
  -H "X-API-Key: $PM_API_KEYS"
```

Это удаляет и настоящую историю переходов тоже. Если истории мало и она всё
равно накопится за вечер — чистить; если за ней месяцы работы — оставить и не
показывать эту карту крупным планом.

Показывать демо-срез никто не мешает: на доске переключатель
«Рабочие / Демо / Все» работает как работал.

---

## 5. Что показывать

Порядок, при котором каждый следующий шаг опирается на предыдущий:

1. **Доска** — партии по этапам, перетаскивание карточки.
2. **Голос** — команда, подтверждение, партия поехала. Сценарий в
   [VOICE-DEMO.md](VOICE-DEMO.md).
3. **Карта процесса** — тот же переход уже в аналитике, видно время на этапах.
4. **Данные 1С** — если разговор пойдёт про деньги: счёт-фактуру выписывают
   через 11.5 дней после отгрузки (медиана по 12 464 документам). Это самая
   надёжная цифра из всего, что удалось вытащить.

---

## 6. Про что сказать самому, не дожидаясь вопроса

Честный ответ заранее звучит лучше, чем пойманная неточность.

- **Связей между документами в 1С нет.** `ДокументОснование` и `Сделка` пусты
  во всех проверенных документах, поэтому кейс склеен как «контрагент + месяц».
  Проследить путь одной сделки эти данные не позволяют.
- **Цифру «43.7% только отгрузка» называть долей нарушений нельзя** — это
  частично артефакт нарезки по календарным месяцам.
- **Точность распознавания в цеху не измерена.** На чистой записи работает,
  рядом с печью — покажут только записи с производства.
- **Периметр рассчитан на локальную сеть.** За её пределы стенд в нынешнем
  виде выпускать нельзя: см. раздел 7 в [HANDOFF.md](HANDOFF.md).

## Если что-то пошло не так

**Доска пустая.** Проверьте переключатель «Рабочие / Демо / Все» — скорее
всего смотрите не на тот срез.

**Карточка не переносится.** Теперь над доской появляется красная плашка с
причиной; раньше отказ выглядел как молчаливый откат. Причина почти всегда —
переход не на соседний этап или блокирующая проблема на партии.

**После правки статики ничего не изменилось.** `Ctrl+F5` — браузер отдаёт
старый JS из кеша.

**Совсем плохо.** Откат к последнему заведомо рабочему состоянию:

```bash
git checkout demo-working && docker compose up -d --build
```
